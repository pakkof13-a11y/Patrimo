# audit-api-authz — cross-audit IDOR sur les 108 routes

Aucun constat. Aucune faille IDOR trouvée.

Toutes les routes examinées vérifient l'appartenance de la ressource à l'utilisateur de la session avant lecture, mutation ou suppression — directement (`where: { id, userId }`) ou via une relation vérifiée (`where: { assetId, asset: { is: { userId } } }`, `where: { id, lifeInsurance: { userId } }`, etc.), soit en délégant à une fonction de service qui applique elle-même ce filtre. Les `updateMany`/`deleteMany` par id seul rencontrés (crypto/defi/valuations/refresh, real-estate/indirect DELETE) sont précédés d'une vérification d'ownership qui rend l'id seul sûr à cet endroit. Le cron refuse tout appel sans CRON_SECRET valide (comparaison temps constant), y compris quand la variable est absente. Le gate admin vérifie le rôle en base (pas seulement le JWT).

Routes vérifiées avec ownership correctement scopé (non exhaustif) : assets/[id]/*, banks/[id]/events, crypto/defi/positions/[id]/* (+services), crypto/nft/[assetId]/* (+services), real-estate/properties/[id]/* (+services), savings/[id]/events, securities/accounts/[id]/* (+services), securities/contributions/[id] (+fiscal-service), tangibles/[id]/valuations (+service), term-deposits/[id], trading/accounts/[id] (+service), ainsi que les collections banks, savings, platforms(+merge), liabilities, life-insurance(+supports,coupons), precious-metals(+sales), employee-savings(+import), crowdlending, private-equity, crypto/futures, crypto/defi/strategies/[id], transactions, wallets/{zerion,solana,monero}/sync, import/commit, real-estate/indirect, real-estate/rent-schedule, envelopes, tax/marginal-rate, preferences/clear-data, auth/change-password.
